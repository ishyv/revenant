# Capability runtime implementation contract

Revenant applications target ordinary hosted URLs first. Browser/WASM is the default; an optional native Rust server is explicitly selected through `app.server`. Desktop is a future host. The public interface expresses collections, selections, operations, tasks, settings and inspectable systems. Transport mechanics are private.

## Package boundaries

The root package remains the CLI. Workspace crates are `crates/revenant-core`, `crates/revenant-sdk`, `crates/revenant-macros`, `crates/revenant-hosts`. The browser package is `packages/client` (`@revenant/client`, source TypeScript exports plus `/svelte` and `/ui`). The SDK version is 0.2.0 and the runtime configuration discriminator is `version = 2`. Unversioned project configurations retain the legacy bridge. New applications alias `revenant-sdk` as `revenant` in Cargo dependencies.

## Shared boundary

All boundaries use JSON-compatible serde contracts with JSON schemas and TypeScript definitions exported programmatically from compiled Rust registrations. A contract manifest includes `version: 2`, `protocol: 1`, `digest`, and `operations`. Each operation has an `id` (for example `media.readMetadata`), `description`, `input` and `output` type definitions. A type definition has `name`, `typescript`, `schema`. Exported dependent definitions must be included. Unsupported serialization and loss-prone numeric contracts fail export; explicit decimal-string large integer wrappers are available. File sizes, modified timestamps and progress counts use canonical decimal strings on every host. JavaScript presentation can convert bounded values to numbers for ratios and human-readable sizes.

Errors are `{code, message, details?, retryable}`. Handles are `{id, scope, generation, kind}` with string ids and scopes. Handles cannot be adopted between scopes; resource access is validated and leased for the duration of a task. A task snapshot is `{id, scope, state, progress, outcomes, result?, error?, cancelRequested}`. Progress is `{completed, total?, message?}`. An outcome is `{index, output?, error?}`. Task states are `queued`, `running`, `cancelling`, `succeeded`, `partial`, `failed`, `cancelled`, `interrupted`. Cancellation requested is distinct from acknowledged cancellation; terminal states are immutable. Partial batch output remains inspectable.

The browser host loads a compiled WASM module providing `manifest()` (JSON manifest), `dispatch(operation, input, context)` (async JSON result), and `cancel(taskId)`, with optional default initialization. Context is `{taskId, scope, resources, read(handle, offset, length), progress, isCancelled, outcome?}`. Resources are trusted file entries, reads return `Promise<Uint8Array>`, and progress uses decimal strings. The optional outcome callback preserves indexed partial results even when dispatch rejects. Heavy Rust work runs in a bounded worker pool; MessagePort chunk brokers transfer buffers under task leases, and browser pickers stay on the main thread.

The native host exposes `/api/contract`, `/api/session`, `/api/tasks`, `/api/tasks/batch`, `/api/tasks/:id`, `/api/tasks/:id/events`, `/api/tasks/:id/cancel`, `/api/upload`, `/api/runtime`, and session/task DELETE routes. A session response is `{token, scope, expiresInMs}`. Bearer tokens own handles, tasks and inspection; EventSource uses `?session=token`. Starting a task takes `{operation, input}`; a batch takes `{operation, inputs}`. Both return snapshots. SSE emits complete `snapshot` events so reconnect recovers current state. Multipart uploads use `file` plus optional `name`, `relativePath`, `mime`, `modified` and return `{task, file}`. Disconnect never falsely acknowledges cancellation. Sessions expire and clean up their files and jobs. Configurable limits bound jobs, queues, sessions, history, batch items, uploads, storage, chunk sizes and SSE connections. Rejected submissions and uploads do not consume hidden history quota. The host crate supplies browser and server features independently.

## Authoring interface

`createApp({wasm?, server?, concurrency?})` creates an application-owned runtime. `useApp()` creates a Svelte component scope against the configured application. `app.files.openFolder()` returns `Collection<FileEntry>`. `collection.selection()` returns reactive `Selection<T>`; `.set(items)` snapshots membership; `.run(operation)` starts a batch task. Collections expose readable state, filter/sort and disposal. Operations expose `.run(input): Task<O>` and `.call(input): Promise<O>`. Tasks are Svelte readable stores with `.result`, `.cancel()` and `.dispose()`; batch outcomes retain original indices. File entries have a scoped handle, name, relativePath, size, mime and modified metadata. Browser absolute paths are never invented.

`app.media.readMetadata` is an operation; `app.media.preview(entry)` owns and returns a disposable preview with URL/kind metadata. `app.settings.define(defaults, {key?})` returns a reactive inferred settings object with `set`, `update`, `flush`, persistence status and disposal. Folder bookmarks are separate from native filesystem paths and permission restoration is explicit. `app.runtime.inspect()`, `.configure(id, config)` and `.replace(id, provider)` expose supported runtime changes. Replacements validate schema and dependencies before activation, reject busy providers/resources, clean up failed candidates and leave the old provider active. TypeScript providers implement generated input/output contracts and are validated at runtime. Server providers are compiled Rust.

## Integration and verification

The reference application opens/browses a folder, filters/sorts/selects files, previews text/image/audio/video, processes metadata with progress and cancellation, downloads partial reports, persists settings and runs a custom chunked Rust checksum. A second ordinary-record collection demonstrates the generic authoring model. The actual current HyvUI library is snapshotted in isolation and used as a replaceable visual layer.

Implementation precedes tests. Compiler/type checks may guide integration; meaningful runtime, contract, browser, server and CLI tests are added and run after the complete workflows exist. Beads is the sole durable task tracker. No commits, pushes or source sibling modifications occur during implementation. The later no-shutdown instruction supersedes the earlier request to schedule a shutdown.
